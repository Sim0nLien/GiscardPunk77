- Date : `2026-08-15`

- Scène de démonstration technique : `Assets/_Project/Scenes/Tests/NpcSandbox.unity`

## En une phrase

Tu peux déjà montrer un FPS où le joueur se déplace, saute, s’accroupit, ouvre des portes et tire ; puis, dans un sandbox séparé, montrer le tir hitscan, la santé, la navigation, le passage de porte, la vision, la suspicion et l’alerte.

## Préparation commune

1. Attends que Unity ait fini de compiler et vérifie que la Console ne contient pas d’erreur rouge actuelle.
2. Pour une démo jouable, ouvre `SampleScene.unity` : c’est la seule scène actuellement mise dans les Build Settings.
3. Pour les bancs techniques, ouvre directement `Assets/_Project/Scenes/Tests/NpcSandbox.unity` ; elle n’a pas besoin d’être ajoutée aux Build Settings pour être jouée dans l’éditeur.
4. Les menus `Create or Update` sont idempotents : ils mettent à jour leur propre racine de banc et peuvent être relancés avant une démo.

## Parcours court : montrer le FPS déjà jouable

1. Ouvre `Assets/Scenes/SampleScene.unity`.
2. Clique sur **Play**.
3. Utilise `ZQSD` ou `WASD` pour bouger, la souris pour regarder, `Espace` pour sauter, `Maj gauche` pour sprinter et `Ctrl gauche` ou `C` pour s’accroupir.
4. Vise une porte à moins de trois mètres et appuie sur `E`.
5. Clique avec le bouton gauche pour le tir prototype physique.

Résultat attendu : le joueur avance dans le wagon, change de vitesse, se baisse, saute et ouvre une porte visée. Le clic gauche crée des capsules-projectiles visibles.

Signe d’échec : si `E` ne répond pas, viser directement le panneau ou le collider de la porte et vérifier que la `Main Camera` est active. Si le joueur ne répond pas, cliquer une fois dans la fenêtre **Game** pour lui donner le focus.

## Parcours technique : tir hitscan et santé

Le tir hitscan est séparé du prototype physique de `SampleScene`. Il sert à montrer des règles de jeu mesurables : impact, dégât, santé, mur, chargeur et recharge.

1. Exécute `Tools > GiscardPunk77 > P03 > Create or Update Hitscan Sandbox`.
2. Unity ouvre ou met à jour `NpcSandbox.unity` dans la racine isolée `P03 Hitscan Test Rig`.
3. Clique sur **Play** ; clique gauche pour tirer et `R` pour recharger.
4. Regarde le panneau en haut à gauche : il indique le chargeur, la réserve, le nom de l’impact et la santé restante de la cible.
5. Tire d’abord sur `Target - Before Wall`, puis vers `Target - Behind Wall` : le mur doit arrêter le tir.

Résultat attendu : le panneau affiche huit coups au chargeur, une réserve, les impacts et les dégâts. Après huit coups, `R` lance une recharge de 1,6 seconde. Un mur empêche le tir d’atteindre la cible placée derrière.

Limite : c’est un banc de test, pas encore l’arme intégrée à la scène principale.

## Parcours technique : capsules, NavMesh et porte

1. Dans `NpcSandbox.unity`, exécute `Tools > GiscardPunk77 > P06 > Create or Update Door Stress Sandbox`.
2. Sélectionne `P04 Navigation Sandbox Generated` dans la Hierarchy et bake son `NavMeshSurface` si Unity indique qu’il n’y a pas de NavMesh.
3. Active **Gizmos** dans la Scene ou la Game view.
4. Entre en Play Mode et observe `P06 Door Traversal Stress`.

Résultat attendu : les capsules traversent le seuil sans que plusieurs occupent la porte simultanément. Les marqueurs jaunes sont des attentes, le trait magenta est le lien de seuil, et les marqueurs verts sont des destinations.

Limite importante : les tests P06 sont validés, mais le contrôle visuel H2 n’a pas encore été rapporté séparément. Présente donc cette séquence comme une démonstration technique à vérifier avec toi, pas comme une séquence finale de jeu.

## Parcours technique : voir, suspecter, alerter

Ces trois étapes expliquent très bien la future IA, même si le garde final n’existe pas encore.

1. Exécute `Tools > GiscardPunk77 > P07 > Create or Update Vision Sandbox`.
2. Puis exécute `Tools > GiscardPunk77 > P08 > Create or Update Awareness Sandbox`.
3. Enfin exécute `Tools > GiscardPunk77 > P09 > Create or Update Alert Service Sandbox`.
4. Dans la Hierarchy, sélectionne `P07 Observer` ou `P08 Observer`, active **Gizmos**, puis lance Play Mode.
5. Pour P07, déplace la cible derrière l’observateur ou place le mur à `X = 0` pendant le Play Mode : le rayon et le résultat de visibilité changent.
6. Pour P08/P09, laisse `P08 Visibility Target` visible : le signal de suspicion apparaît, puis le `!` rouge. Sélectionne `P09 Alert Service Test Rig` pour voir l’`AlertService` passer à `Alerted`.

Résultat attendu :

- P07 dessine le cône de vision et un rayon vert si la cible est vue, rouge si un mur bloque ;
- P08 passe de calme à suspicion puis à alerte et affiche `!` ;
- P09 mémorise une seule alerte de scène au lieu de suivre continuellement la cible.

Signe d’échec : si la mauvaise caméra est affichée dans **Game**, désactive temporairement les caméras des autres bancs de test pendant la démonstration, sans sauvegarder la scène. Chaque banc a sa propre caméra de présentation.

## Ordre conseillé pour une démo de dix minutes

1. Deux minutes dans `SampleScene` : déplacement, porte, tir prototype.
2. Trois minutes dans le banc P03 : tir hitscan, dégâts, mur et recharge.
3. Deux minutes dans P06 : capsules qui se coordonnent à la porte.
4. Trois minutes dans P07, P08 et P09 : « voir → suspecter → alerter ».

Cette progression raconte une histoire simple : le joueur sait se déplacer et agir, les cibles peuvent être touchées, les capsules savent se déplacer et partager une porte, puis elles savent voir et transmettre une alerte.

## Ce qu’il ne faut pas promettre aujourd’hui
