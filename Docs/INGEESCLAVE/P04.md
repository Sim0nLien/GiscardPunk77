# P04 — Comprendre Sandbox wagon et NavMesh stable

- Lot : `P04`
- Statut : `complete — continuité P05 autorisée`

- Rapport technique associé : `.agents/ingeesclave/REPORTS/P04.md`

## En une phrase

P04 construit un petit wagon-laboratoire où Unity calcule les zones accessibles à une capsule et relie explicitement les deux sols séparés par le seuil d’une porte.

## Pourquoi ce changement existe

Une navigation qui fonctionne dans une grande pièce peut échouer dans un train : couloir trop étroit, virage sans marge, deux agents face à face ou petite coupure au seuil. Tester ces risques dans `NpcSandbox` évite de modifier `SampleScene` et permet de mesurer avant de construire le vrai moteur PNJ.

La scène est produite par un outil idempotent. Le relancer remet à jour les objets connus sans dupliquer la racine ni toucher une éventuelle racine P03.

## Vocabulaire utile

| Mot | Explication simple |
|---|---|
| NavMesh | Surface bleue calculée par Unity sur laquelle un agent est autorisé à se déplacer. |
| `NavMeshSurface` | Composant AI Navigation qui choisit la géométrie à analyser et les paramètres du bake. |
| Bake | Calcul Editor qui transforme les colliders du wagon en données de navigation. |
| `NavMeshLink` | Passage explicite reliant deux morceaux de NavMesh séparés. |
| Rayon | Demi-largeur de l’agent ; Unity érode les bords selon cette valeur. |
| Évitement | Correction locale par laquelle les agents tentent de ne pas se percuter. |
| Gizmo | Dessin visible dans la Scene View pour expliquer une information invisible dans le jeu. |

## Comment les pièces travaillent ensemble

```text
Colliders de la racine P04
          ↓ Bake manuel H2
NavMeshSurface ── deux îlots marchables
          ↓
NavMeshLink au seuil de porte
          ↓
NavMeshAgent du probe ── SetDestination
          ↓
Destinations et trajet observables par gizmos
```

| Fichier | Responsabilité |
|---|---|
| `NpcSandboxTuning.cs` | Une seule source pour les mesures initiales. |
| `NpcSandboxAgentProbe.cs` | Parcours de démonstration temporaire ; il ne déplace jamais directement le `Transform`. |
| `NpcSandboxNavigationGizmos.cs` | Dessine les zones et marqueurs sans décider du déplacement. |
| `NpcSandboxNavigationAuthoring.cs` | Crée ou met à jour uniquement la racine P04 de la scène. |

## Explorer pas à pas

1. Ouvrir `NpcSandboxTuning.cs` : les mesures qui doivent rester cohérentes sont réunies au même endroit.
2. Ouvrir `NpcSandboxNavigationAuthoring.cs` : repérer `collectObjects = Children`. Le bake est ainsi limité aux enfants de la racine P04.
3. Ouvrir `NpcSandboxAgentProbe.cs` : seul `NavMeshAgent.SetDestination` demande un déplacement ; aucune ligne n’écrit la position du `Transform`.
4. Ouvrir `NpcSandboxTuningTests.cs` : les tests expliquent pourquoi 1,5 m forme un couloir individuel tandis que 4,6 m permet un croisement.

### Valeurs initiales de la capsule

| Réglage | Valeur | Raison initiale |
|---|---:|---|
| Type de bake | Humanoid, ID 0 | Profil déjà enregistré dans le projet. |
| Rayon | 0,5 m | Identique au rayon du bake Humanoid. |
| Hauteur | 2 m | Identique à la hauteur du bake Humanoid. |
| Vitesse | 3,5 m/s | Marche rapide lisible pour un test, sans sprint. |
| Accélération | 12 m/s² | Démarrage net sans changement instantané de vitesse. |
| Rotation | 360°/s | Permet les demi-tours dans la baie. |
| Évitement | Haute qualité | Référence prudente pour les futurs tests à plusieurs agents. |
| Priorité | 50 | Valeur neutre au milieu de l’échelle 0–99. |
| Distance d’arrêt | 0,08 m | Suffisamment petite pour valider précisément les marqueurs. |

Le `NavMeshSurface` utilise des colliders physiques, des voxels de `0,125 m`, des tuiles de `128` voxels et une région minimale de `0,5 m²`. Le NavMesh n’est jamais rebâti à chaque image.

## Essayer sans risque

### 1. Créer ou remettre à jour la scène

Dans Unity, choisir :

`Tools > GiscardPunk77 > P04 > Create or Update Navigation Sandbox`

Puis ouvrir `Assets/_Project/Scenes/Tests/NpcSandbox.unity`. La Hierarchy doit contenir une seule racine `P04 Navigation Sandbox Generated`. Relancer le menu ne doit pas la dupliquer.

### 2. Observer les gizmos

Activer `Gizmos` dans la Scene View et sélectionner `Markers and Gizmos` :

- cyan : zones marchables prévues ;
- magenta : lien du seuil ;
- jaune : deux points d’attente ;
- vert : destinations ;
- rouge : deux positions de tir.

### 3. Bâtir le NavMesh — porte H2

1. Sélectionner `P04 Navigation Sandbox Generated`.
2. Dans son composant `NavMeshSurface`, cliquer `Bake`.
3. Vérifier que la surface bleue couvre les deux sections, le couloir et la baie.
4. Vérifier que les deux surfaces séparées au seuil sont reliées par le lien magenta.
5. Passer en Play Mode et regarder la capsule dans la Scene View : elle doit parcourir les deux sections et franchir la porte dans les deux sens.

Résultat attendu : aucun message NavMesh répété, aucun blocage au seuil et toutes les destinations atteintes.

Signe d’échec : une section sans surface bleue, un lien dont une extrémité ne touche pas le NavMesh, `Failed to create agent`, `SetDestination can only be called...` ou une capsule immobile après le bake.

## Ce que ce lot ne fait pas

- Le probe est un instrument de P04, pas l’API finale de déplacement.
- `NpcMotor`, les statuts de chemin et la récupération d’échec appartiennent à P05.
- La porte est ouverte visuellement ; interaction et réservation appartiennent à P06.
- Aucun agent n’est ajouté à `SampleScene`.
- Aucun rebake NavMesh n’est exécuté au runtime.
