## En une phrase

Unity Behavior choisit l'ordre des actions, tandis que les composants C# restent responsables de la santé, de la perception, de l'alerte et du déplacement.

## Le dessin mental

```text
Behavior Graph
  -> lit NpcContext
  -> choisit une destination écrite
  -> demande à NpcMotor de s'y rendre
  -> attend le résultat public du moteur

NpcMotor -> seul propriétaire de NavMeshAgent
NpcVisionSensor -> seul capteur visuel
NpcAwareness -> seule suspicion individuelle
AlertService -> seul niveau d'alerte de scène
Health -> seule propriétaire de la santé et de la mort
```

Le graphe est donc un chef d'orchestre : il donne le départ, mais il ne joue pas lui-même de tous les instruments.

## Vocabulaire utile

- **Behavior Graph** : asset visuel qui relie des nodes de haut en bas.
- **Node** : petite condition ou action avec une seule responsabilité.
- **Blackboard** : tableau de variables partagées par les nodes d'une instance du graphe.
- **Behavior Agent** : composant placé sur un GameObject pour exécuter un graphe.
- **Condition** : question booléenne, par exemple « le PNJ est-il mort ou l'alerte globale est-elle active ? ».
- **Abort** : node Behavior qui interrompt une branche lorsque sa condition devient vraie.
- **Contexte explicite** : objet qui contient des références assignées ; il évite les recherches globales et les dépendances cachées.

## Pourquoi le package est embarqué

Behavior 1.0.13 est la version confirmée du projet. Elle a été publiée pour Unity 6000.0, alors que ce projet est en 6000.5.5f1. Unity 6000.5 remplace plusieurs identifiants entiers par `EntityId` et une API de drag-and-drop, ce qui faisait échouer dix appels répartis dans sept fichiers du package.

Le package reste en version 1.0.13 mais sa copie est placée dans `Packages/com.unity.behavior`. De petits blocs conditionnels adaptent ces appels à Unity 6000.5. Cette méthode est visible, versionnable et réversible quand Unity publiera une version officiellement adaptée. Aucune autre version directe du manifeste n'a été changée.

## Responsabilité de chaque fichier

- `AI/Behavior/NpcContext.cs` : contient les six références explicites et produit une erreur précise si une dépendance manque.
- `AI/Behavior/NpcStateReader.cs` : traduit les états publics des composants en réponses simples.
- `AI/Behavior/Nodes/NpcStateCondition.cs` : rend ces réponses utilisables par `Conditional Guard` ou `Abort`.
- `AI/Behavior/Nodes/NpcWaitAction.cs` : attend une durée configurable et respecte la pause grâce à `Time.deltaTime`.
- `AI/Behavior/Nodes/NpcChooseDestinationAction.cs` : copie la position d'un objet choisi dans le Blackboard.
- `AI/Behavior/Nodes/NpcMoveToDestinationAction.cs` : appelle `NpcMotor.TrySetDestination` et observe son statut.
- `Editor/NpcBehaviorGraphAuthoring.cs` : crée ou ouvre uniquement l'asset de banc P10.

## Leçon : déléguer au lieu de recopier

Il aurait été tentant de mettre un `NavMeshAgent` dans le node de mouvement. Ce serait une deuxième autorité de navigation : `NpcMotor` et le node pourraient alors se contredire, gérer différemment les échecs ou oublier d'annuler une route.

Le node P10 fait trois choses seulement : envoyer une commande au moteur, traduire son statut en `Running/Success/Failure`, puis annuler sa propre route à la fin ou lors d'un Abort. La logique NavMesh reste testable au même endroit qu'avant.

## Comment créer et ouvrir le graphe

1. Si Unity vient d'importer le package embarqué, attendre la fin de la roue de progression. Si la Console affiche encore un chemin `Library/PackageCache/com.unity.behavior...`, fermer puis rouvrir le projet pour purger l'ancienne compilation.
2. Ouvrir `Window > Package Management > Package Manager` et sélectionner **Behavior**.
3. Vérifier `Version 1.0.13` et la source **Embedded**.
4. Exécuter `Tools > GiscardPunk77 > P10 > Create or Open Minimal Behavior Graph`.
5. L'outil ouvre `Assets/_Project/Config/AI/P10 Minimal NPC Behavior.asset`.

Le graphe doit contenir :

```text
Start
  -> NPC Choose Destination
  -> NPC Move To Destination
  -> NPC Wait
```

L'outil est idempotent : un second clic ouvre l'asset existant sans effacer les ajustements effectués dans l'éditeur.

## Préparer un agent de test dans NpcSandbox

1. Ouvrir `Assets/_Project/Scenes/Tests/NpcSandbox.unity`.
2. Sélectionner `P04 Navigation Sandbox Generated`, puis **Bake** sur son `NavMeshSurface` si nécessaire.
3. Choisir la capsule de navigation P04 qui possède déjà `NpcMotor`.
4. Ajouter `ActorIdentityComponent`, `Health`, `NpcVisionSensor`, `NpcAwareness` et `NpcContext` si ces composants ne sont pas déjà présents.
5. Créer ou réutiliser un GameObject de scène portant `AlertService`.
6. Dans `NpcContext`, assigner explicitement Identity, Health, Motor, Vision, Awareness et Alert Service.
7. Faire glisser `P10 Minimal NPC Behavior.asset` du Project sur la capsule. Unity ajoute et configure un **Behavior Agent**.
8. Dans les variables exposées du Behavior Agent, assigner :
   - `Context` : le `NpcContext` de la capsule ;
   - `Destination Source` : un gizmo/destination P04 atteignable.

Cette configuration reste manuelle pour que l'apprenant voie les liens réels au lieu de recevoir une scène opaque.

## Déboguer en temps réel

1. Garder le graphe ouvert.
2. Dans sa barre d'outils, cliquer sur **Debug**.
3. Choisir la capsule qui porte le Behavior Agent.
4. Entrer en Play Mode.
5. Observer les statuts directement sur les nodes : choix instantané, mouvement en cours, arrivée, puis attente.

## Expérience sans risque : moteur désactivé

1. Sortir du Play Mode.
2. Désactiver uniquement le composant `NpcMotor` de la capsule.
3. Relancer le Play Mode avec le même agent sélectionné dans **Debug**.
4. Observer le node `NPC Move To Destination`.

Résultat attendu : le node passe en `Failure` et la Console affiche une erreur lisible contenant `NpcMotor is disabled; movement was not started.` Il ne doit y avoir ni `NullReferenceException`, ni déplacement direct, ni spam à chaque frame.

Réactiver ensuite `NpcMotor` pour remettre le banc dans son état normal.
