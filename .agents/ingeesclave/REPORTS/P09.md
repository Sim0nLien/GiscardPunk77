## Comment voir le changement

1. Dans `Window > General > Test Runner`, lancer `GiscardPunk77.AI.Tests` en Edit Mode : les quatre `AlertServiceTests` doivent être verts.
2. Exécuter d'abord `Tools > GiscardPunk77 > P08 > Create or Update Awareness Sandbox`, puis `Tools > GiscardPunk77 > P09 > Create or Update Alert Service Sandbox`.
3. Ouvrir `Assets/_Project/Scenes/Tests/NpcSandbox.unity`, sélectionner `P09 Alert Service Test Rig`, puis passer en Play Mode.
4. Quand `P08 Observer` atteint `Alerted`, lire `Level`, `Has Initial Observation`, le point et l'heure sur `AlertService`.
5. Dans le menu contextuel du composant, lancer `P09/Reset Alert` : l'état revient à `Calm` et l'instantané est effacé.

## Résultat attendu

- Une seule transition `Alerted` est diffusée, même si le garde reste alerté ou si un autre reporter tente d'alerter ensuite.
- Le premier point/temps reste inchangé après un déplacement de la cible : il est une copie de valeurs, pas un suivi.
- Tout composant recevant explicitement la référence peut lire `service.Level` immédiatement, y compris s'il arrive après l'alerte.
- Reset publie seulement le retour réel vers `Calm` et remet l'instantané à vide.

## Signe d'échec

- Plusieurs broadcasts pour la même alerte, une position qui continue de bouger, un appel à un singleton global, un abonnement qui réagit après disable ou un test rouge bloquent P09.

## Limites

- P09 ne déplace aucun garde et ne crée aucune investigation vers l'instantané.
- Le service n'est pas une persistance entre scènes, un réseau d'alerte ou une gestion de factions.
- Les quatre tests Unity restent à lancer dans Test Runner; seules les compilations ciblées ont été exécutées ici.
