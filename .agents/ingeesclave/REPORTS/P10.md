## Objectif et périmètre

- Objectif : adopter Unity Behavior comme orchestrateur sans déplacer la logique métier dans ses nodes.
- Inclus : Behavior 1.0.13, compatibilité Unity 6000.5, audit des asmdefs, `NpcContext`, nodes génériques minimaux, outil de graphe, erreurs explicites, tests, rapport et guide.
- Exclu : graphe final du garde, P11, GOAP, combat, package tiers supplémentaire et modification de `SampleScene`.

### T02 — Installer, auditer et rendre Behavior reproductible

- Statut : `complete`
- Action réalisée : `com.unity.behavior` 1.0.13 est la seule dépendance directe ajoutée. Les huit asmdefs réels ont été lus avant de référencer AI.
- Assemblies auditées : runtime `Unity.Behavior`, `Unity.Behavior.Serialization`, `Unity.Behavior.SerializableGUID`; Editor-only `Unity.Behavior.Authoring`, `Unity.Behavior.Editor`, `Unity.Behavior.GraphFramework`, `Unity.Behavior.Serialization.Editor` et `Unity.Muse.Behavior`.
- Dépendance retenue : `GiscardPunk77.AI` référence seulement `Unity.Behavior`; aucun code runtime projet ne référence l'authoring ou l'éditeur.
- Compatibilité : la version publiée vise Unity 6000.0, tandis que le projet utilise 6000.5.5f1. Le package est donc embarqué sous `Packages/com.unity.behavior` avec dix adaptations d'appels réparties dans sept fichiers, toutes conditionnelles à `UNITY_6000_5_OR_NEWER`, vers les API `EntityId`/drag-and-drop actuelles. Son `package.json` reste en version 1.0.13 et aucune autre version directe du manifeste n'a changé.
- Preuve : `packages-lock.json` indique `version: file:com.unity.behavior`, `source: embedded`. La reprise des commandes Roslyn générées par Unity compile sans erreur les assemblies Serialization, Authoring, Editor et Muse de Behavior, puis AI, ses tests Edit/Play Mode et `Assembly-CSharp-Editor`.

### T03 — Créer le contexte et les nodes minces

- Statut : `complete`
- Action réalisée :
  - `ActorIdentityComponent` rend `ActorIdentity` assignable dans l'Inspector ;
  - `NpcContext` expose identité, santé, moteur, vision, awareness et service d'alerte, avec diagnostic ciblé ;
  - `NpcStateReader` et `NpcStateCondition` lisent seulement les états possédés par ces composants ;
  - `NpcWaitAction` utilise le temps de frame mis à l'échelle ;
  - `NpcChooseDestinationAction` copie la position d'un objet explicitement référencé ;
  - `NpcMoveToDestinationAction` commande uniquement `NpcMotor` et annule sa route lors d'une interruption ;
  - `DeadOrGloballyAlerted` est prévu pour la condition d'un node Behavior `Abort`.
- Architecture : aucun node ne raycaste, n'applique de dégâts, ne cherche un objet dans la scène, ne déplace le `Transform` et ne manipule `NavMeshAgent`.
- Erreurs prévues : contexte, source ou sortie absents ; moteur désactivé ; destination rejetée ; route annulée ou moteur en échec.
- Tests ajoutés : deux tests `NpcContext` et trois tests `NpcStateReader`.

### T04 — Créer le graphe minimal et préparer H4

- Statut : `waiting_human`
- Action réalisée : `NpcBehaviorGraphAuthoring` fournit le menu idempotent `Tools > GiscardPunk77 > P10 > Create or Open Minimal Behavior Graph`.
- Asset prévu : au premier clic, l'outil génère `Assets/_Project/Config/AI/P10 Minimal NPC Behavior.asset` avec `Start -> Choose Destination -> Move To Destination -> Wait`, plus les variables exposées `Context` et `Destination Source`.
- Isolation : l'API d'authoring 1.0.13 est interne ; la réflexion reste confinée au script Editor et ne traverse pas l'asmdef AI runtime.
- Comportement idempotent : si l'asset existe, l'outil l'ouvre sans le réécrire ; s'il trouve un autre type d'asset au même chemin, il s'arrête avec une erreur précise.
- Validation tardive du 2026-08-20 : Unity a rafraîchi le projet et les cinq tests P10 passent dans la suite AI `28/28`. Restent la création/ouverture du graphe minimal P10, le debug Play Mode et l'échec lisible avec moteur désactivé.

## Comment voir le changement

1. Laisser Unity terminer le refresh ou fermer/réouvrir le projet si la Console montre encore une ancienne erreur venant de `Library/PackageCache`.
2. Vérifier dans Package Manager que Behavior affiche toujours la version `1.0.13` et la source `Embedded`.
3. Lancer `GiscardPunk77.AI.Tests` en Edit Mode ; les cinq tests P10 doivent être verts avec les tests précédents.
4. Exécuter `Tools > GiscardPunk77 > P10 > Create or Open Minimal Behavior Graph`.
5. Suivre le protocole débutant détaillé dans `Docs/INGEESCLAVE/P10.md` pour connecter un agent du sandbox, ouvrir le graphe et sélectionner **Debug**.
6. Refaire une exécution après avoir désactivé `NpcMotor` sur cet agent.

## Résultat attendu

- Le graphe montre `Start`, `NPC Choose Destination`, `NPC Move To Destination`, puis `NPC Wait`.
- En Play Mode, le flux est surligné et l'agent rejoint la destination par `NpcMotor`.

## Signe d'échec

- Une erreur de compilation actuelle, un node absent du menu, un graphe impossible à ouvrir, un déplacement qui contourne `NpcMotor`, ou une absence d'erreur lorsque le moteur est désactivé bloque H4.
